# 工程侧发现（2026-09-12）：真正的阻塞是**求解时条件数 ~1e35**

本轮把三个先前的诊断逐个实测，两个被推翻，第三个被量化。所有数字都来自本目录的 JSON。

## 0. 一句话

**头条：M=50、L=10、纯幺正、去掉 B（= 2309 的字面设定）→ `certified=True`，
f00(3) = 2.216110，距数字化 Fig.3 的 2.2329 仅 −0.75%（C1 判据 ±2%）。**
这是本项目第一次在论文分辨率上拿到认证点，而它靠的是**删掉一条论文里没有的约束**
（从 arXiv:2403.10772 的代码搬来的 `‖ρ‖₄ ≤ 377500`），不是加精度。详见 §4a。


阻塞既不是算子装配精度，也不是 Watson 退化本身，而是**内点法 KKT 系统的条件数约 10³⁵，
而双精度只有 10¹⁶**。这一条同时解释了此前观察到的全部失败模式，并且让 SDPB 从"可选的
高精度基准臂"变成**必需的主求解器**。

## 1. 被推翻的诊断 A：算子装配精度

**此前的说法**（我在本轮早些时候提出）：Λ₁₉(s₁)² ≈ 1.03e−80 需要约 95 位有效数字，双精度
装配得到的是舍入噪声，约 1650/3000 行退化成 `0 ≤ 0`。

**实测**（`S0_assembly_precision.json`，M=50, L=10）：

| 量 | 值 |
|---|---|
| 行数 | 1500 |
| 行幅度跨度 | 5.10e−85 .. 3.35e+01 |
| **恰好为零的行** | **0** |
| 低于 1e−300 的行 | 0 |
| 低于 1e−16 的行 | 358（不是 1650） |

**没有任何一行下溢。** `legendreq.q_table` 在 mpmath 里以自适应精度算 Q_ℓ 再转 float64，
所以每个行元素在它自己的微小尺度上保有完整的双精度**相对**精度。被离心压低的行是**松弛**
而非退化：圆盘 |h|² ≤ 2 Im h 半径约 1，而那里 |h| ~ 1e−60。

**诊断 A 作废。**

**但顺带找到并修掉了一个真 bug**：`grid.lambda_rescale` 的 `floor=1e-8` 使
`assembly.lambda_analytic` 被截断在 1e−16，"解析 Λ²"报出来的不是它声称的东西。已改为
`floor=0`（返回真值），并在 docstring 里记下实测caveat。

**附带的实质发现**：解析 Λ_ℓ² **根本不描述**装配出来的行幅度——在 Λ²>1e−7 的 857 行上，
实测/解析之比 min 2.95e−4、median 6.91e−3、max 33.5，横跨五个数量级。所以任务书里
`cone_scaling="centrifugal"` 这个处方是错的；`"rownorm"`（实测幅度）才是能用的那个。

## 2. 被推翻的诊断 B：Watson 锁相使求解器失败

**此前的说法**（`TASK_SDP_AUDIT_AND_CLOSE_ZH.md` §6 D3）：幺正饱和处 (3.68) 的 2×2 块奇异，
Slater 失效，`uv_parts=("gram",)` 单独就使求解失败。

**实测**（`S4b_watson_probe.json`，M=20/30，MOSEK 与 Clarabel，可行性与极值各一次）：

| M | 求解器 | 模式 | 状态 | f00(3) |
|---|---|---|---|---|
| 20 | MOSEK | 可行性 / 极值 | optimal / optimal | — / 0.085334 |
| 20 | CLARABEL | 可行性 / 极值 | optimal / optimal | — / 0.083781 |
| 30 | MOSEK | 可行性 / 极值 | optimal / optimal | — / 0.085063 |
| 30 | CLARABEL | 可行性 / 极值 | optimal / optimal | — / 0.084359 |

**`uv_parts=("gram",)` 八次全部 `optimal`。** 加上约束生成后更是 `certified=True`
（f00 = 0.084623，6 轮，357 个圆盘）。

**而 Watson 锁相本身被实测确认，并且求解器扛得住。** 本轮推导：把 `problem._gram_psd` 的
实 3×3 形式

```
[[1+S_re,     S_im,       √2 F_re],
 [S_im,       1−S_re,     √2 F_im],
 [√2 F_re,    √2 F_im,    ρ     ]] ⪰ 0
```

的左上 2×2 行列式算出来正是 **1 − |S|²**；饱和处零向量 (−S_im, 1+S_re)，PSD 强制

```
W := −S_im·F_re + (1+S_re)·F_im → 0     即  arg 𝓕 = δ
```

实测（相对残差 W/(|F|(1+|S|))）：

| M | 求解器 | 波 | 最饱和节点的 1−\|S\| | 该节点的 Watson 残差 |
|---|---|---|---|---|
| 20 | MOSEK | P1 | 2.1e−10 | **9.9e−10** |
| 20 | CLARABEL | P1 | 4.8e−12 | **6.7e−13** |
| 30 | MOSEK | P1 | 8.5e−11 | **3.4e−10** |
| 30 | CLARABEL | P1 | 1.3e−12 | **2.7e−14** |

残差严格跟着 1−|S| 走，一路到 1e−14。**Watson 定理在数值上成立，且不构成求解阻塞。**

**诊断 B 作废**（作为"阻塞"的说法）；作为**物理机制**它被确认了。

## 3. 真正的阻塞：条件数 ~1e35

用本轮新写的 `smatrix_bootstrap.sdp.pmp` 把同一个 ModelSpec（M=20, L=6, 手征 + Gram）
写成 SDPB 的 PMP，在 512 bit 下求解，读它自带的逐迭代诊断（`S2_conditioning.json`）：

| 量 | 首次迭代 | 最大 | 末次 |
|---|---|---|---|
| **Q_cond_number**（Schur complement） | 2.17e+29 | **6.01e+34** | 5.83e+34 |
| max_block_cond_number | 2.00 | 1.55e+22 | 1.55e+22 |

**27/27 次迭代的条件数全部超出双精度可及范围。** 问题需要约 **34.8 位十进制**，双精度给 15.95 位。

这一条解释了此前**全部**失败模式：

| 观察 | 解释 |
|---|---|
| 一次性上全部 3LM 个圆盘 → 任何 M 上都 SolverError | KKT 无法在双精度下分解 |
| 约束生成在圆盘数变大后死掉（M=50：981 个圆盘时求解器失败） | 圆盘越多条件数越差 |
| MOSEK 在 UV 三元组上报 `Problem status UNKNOWN`，迭代点范数 3e10 | 同上 |
| 把 MOSEK 的锥相对间隙从 1e−8 收到 1e−10，第 1 轮就失败 | 要求的精度超过双精度在该条件数下能给的 |

最后一条是我自己踩的坑：本轮第一版口径网格用了 1e−10，24 个格子只解出 4 个；换回模块默认的
1e−8，同一批格子解出 18 个、其中若干 `certified=True`。**这是可复现的实测效应，不是猜测。**

## 4. M=50 的真实状态

`S0_m50_pure_report.json`（纯幺正，MOSEK，约束生成，B=377500 l4）：

- 状态 `optimal`，30 次迭代，**777 s** —— **M=50 是解得动的**
- 但 `certified=False`：生成循环走了 10 轮，加到 **981 个圆盘时求解器失败**
- 返回 f00(3) = **3.5736**，比数字化 Fig.3 的 2.2329 高 **60%**

这不矛盾：未认证的松弛值是真极值的**上界**。所以正确的说法不是"M=50 不收敛"，而是
**"M=50 解得动，但认证不了"**——认证需要把圆盘加满，而圆盘一多条件数就超出双精度。

变体（`m50_variants.json`）：`B_norm="l2"` 在 M=50 上第 1 轮即 SolverError（20.6 s），
反而比 l4 更差。

## 4a. ★ 去掉 B：M=50 的第一个认证点

`S0_m50_certified_without_B.json`。同一个问题（M=50, L=10, 纯幺正, MOSEK, 约束生成）：

| B | 状态 | 认证 | f00(3) | 备注 |
|---|---|---|---|---|
| `‖ρ‖₄ ≤ 377500` | optimal | 否 | 3.5736 | 981 个圆盘处失败，高 60% |
| `‖ρ‖₂ ≤ 377500` | SolverError | — | — | 第 1 轮即死（20.6 s） |
| `‖ρ‖₂` + 精确基约化 | optimal | 否 | 4.7412 | 681 个圆盘处失败，max_viol 8.4e39 |
| **无 B** | optimal | **是** | **2.216110** | 22 轮，1428/1500 圆盘，620 s |

**B 不在 2309 里。** 论文全文没有任何正则化；这条是从作者后续论文 2403.10772 的代码
（`norm(rho/Mrho,4) <= 1e2`）搬来的。实测表明它**本身就是数值阻塞的主要成分**。

这同时回答了物理侧 Q2 的一半：**纯幺正扇区在 2309 的字面设定下可行、有界、认证**，
并且落在 Fig.3 的 ±2% 内。B 不需要，也不该有。

## 5. 口径网格（M=20, L=6，24 个格子）

`S3_caliber_grid_M20.json`。这是给物理侧的证据面：论文的对照（仅手征 → 无 ρ；加 UV → 有 ρ）
在整个口径网格上的表现。

**求解 18/24，但只有少数 `certified=True`。**未认证的 f00 值（0.4–1.0）是松弛上界，
比论文的 ~0.08 高一个量级，**不可用作物理结论**。

已认证的格子：

| 扇区 | χ | SR | B | f00(3) | ρ (GeV) |
|---|---|---|---|---|---|
| 仅手征 | chi-b | — | 377500 | 0.084314 | 1.497 |
| 仅手征 | chi-b | — | 无 | 0.086224 | 无 |
| 仅手征 | chi-c | — | 377500 | 0.086584 | 1.366 |
| 仅手征 | chi-c | — | 无 | 0.091349 | 无 |
| 手征+UV | chi-b | SR-a | 377500 | 0.081480 | 1.418 |

**chi-a（论文字面的 L∞ 盒）表现迥异**：带 B 时 `cert=False` 且 f00 = 1.26，不带 B 时
SolverError。这是给物理侧 Q3 的一个硬数据点。

**本轮还不能回答论文的对照**，因为认证率太低——这正是 §3 那个条件数问题的直接后果。

## 6. 由此得出的工程结论

1. **SDPB 不是可选项，是主求解器。** 512 bit ≈ 154 位十进制，比需要的 ~35 位宽一个数量级。
   双精度求解器（MOSEK/Clarabel）只能在圆盘子集上工作，因而只能给未认证的上界。
2. 本轮已把 PMP 写入器（`src/smatrix_bootstrap/sdp/pmp.py`）建好并**用已知答案验证过**
   （旋转二阶锥 x²+z² ≤ 2w，精确解 x=2，SDPB 512 bit 返回 2.0000…0007，gap 3.7e−31）。
3. 下一步的工程重点从"修装配精度"改为"**让 SDPB 在完整圆盘集上跑完**"——它不需要约束生成，
   因为它不受条件数限制。规模估算与编码配方见 `TASK_SDP_PIPELINE_ZH.md` §3。

## 7a. SDPB 路径的两个坑（都已修进运行器）

1. **`/dev/shm` 默认 64 MB**：SDPB 用 MPI 共享内存窗口，M=20 的问题就要 320 MB，
   不给 `--shm-size` 会在 `MPI_Win_allocate_shared` 报 `MPI_ERR_INTERN` 并中止。
   已在 `scripts/sdpb/sdpb.sh` 加 `--shm-size ${SDPB_SHM:-16g}`。
2. **PMP 的嵌套层数**：`polynomials[row][col][variable]` 里每个变量必须是它**自己的**系数列表
   （degree-0 即单元素列表）。写成扁平列表会让 pmp2sdp 报
   `Not implemented: json_string in Json_Polynomial_Parser`。已修，已知答案测试通过。

规模实测：M=20 L=6 手征+Gram → pmp.json 25 MB / 401 块 / 732 变量，pmp2sdp 426 s。
M=50 L=10 纯幺正 + 精确基约化 → 421 MB / 1500 块 / 1780 变量。
